# BlockMarket v1 原型规则契约

规则标识：`blockmarket-v1-prototype.2`。这是当前技术原型的冻结契约，不等于联创正式赛规。

## 1. 参数

| 参数 | 值 |
| --- | ---: |
| 玩家 | A、B |
| 默认区块数 | 300 |
| 初始现金 | 10000.00 |
| 初始库存 | 50 |
| 库存范围 | 0–100 |
| 合法价格 | 50.00–150.00 |
| 最小价格步长 | 0.01 |
| 单边最大数量 | 10（整数） |
| 成交费率 | 5 bps |
| 知情订单概率 | 10% |
| 公开方向信号准确率 | 65% |
| 客户基础激进度 | 0.50–3.50 |
| 参考价隐藏噪声幅度 | ±5.00 |
| Decimal 精度 | 50，ROUND_HALF_EVEN |

`cash` 记录未扣费现金流，`fees` 单独累计；可用现金与财富使用 `cash - fees`。终局财富为：

```text
wealth = cash + inventory * terminal_price - fees
```

## 2. 每轮公开信息与动作

Bot 在同一轮只收到自己的 observation，不会看到对手本轮动作。公开信息包括：

- 当前及历史参考价；
- 当前及历史 `UP` / `DOWN` 信号；
- 自己的现金、库存、费用和按当前参考价计算的权益；
- 上轮公开成交、双方累计成交量、剩余轮数和风险边界。

隐藏信息包括环境初值、`orderflow_key`、本轮客户订单类型、方向、数量和保留价。隐藏材料在赛后回放中揭示，供独立复核。

动作必须只有 `decision_seq`、`bid`、`ask` 三个字段。每侧要么为 `null`，要么严格包含十进制字符串 `price` 和 `quantity`。价格必须两位小数、数量必须是 `1`–`10` 的整数字符串；禁止指数、前导加号、负零、多余字段和 `bid >= ask`。

任何错误整条拒绝，本区块按 `HOLD`，稳定错误码写入事件；引擎不裁剪或猜测。

## 3. 参考价、信号和客户订单

二阶隐藏状态以 50 位十进制递推：

```text
x_next = 1 - 1.4 * x_cur^2 + 0.3 * x_prev
```

任一状态绝对值超过 `4` 时整场失败。每轮参考价为稳定基线加隐藏确定性噪声：

```text
reference = tick(clamp(100 + 8 * x_cur + noise[-5, +5], 50, 150))
```

噪声由 `SHA-256(orderflow_key, block_seq, lane)` 确定，不依赖 Bot、时间或机器。公开方向信号以 65% 概率正确指向下一轮参考价的涨跌。

客户订单分两类：

- `noise`（90%）：买卖方向由独立确定性随机 lane 给出；
- `informed`（10%）：方向与下一轮真实参考价变化一致，并可获得额外激进度，因此容易对过窄报价形成逆向选择。

订单数量为 1–10，保留价为当前参考价加减客户激进度。具体映射在 `src/blockmarket/orderflow.py`，独立复核器在不调用该模块的情况下重新实现同一规则。

## 4. 成交

- 客户买单消费 Bot 的 `ask`：报价不得高于客户保留价，最低价优先。
- 客户卖单消费 Bot 的 `bid`：报价不得低于客户保留价，最高价优先。
- 只有最优价格层成交，不向次优价继续扫单。
- 同价时先按实际可成交容量做整数比例分配；余数按最大分数余数优先，完全相等时用公开 `tie_break_offset + block_seq` 轮换。
- 实际容量同时受报价量、库存边界和扣费后可用现金约束。

## 5. 记账与得分

Bot 买入：`cash -= notional`、`inventory += quantity`、`fees += fee`。卖出反向更新现金和库存，费用仍增加。每次更新后必须满足扣费后现金非负、库存位于 `[0, 100]`。

```text
initial_wealth = initial_cash + initial_inventory * opening_reference_price
score_A = (wealth_A - wealth_B) / initial_wealth
score_B = -score_A
```

终值价格只由推进后的环境决定，不读取玩家报价或成交价。所有成功对局必须精确满足 `score_A + score_B == 0`。

## 6. 审计

manifest 的 canonical JSON SHA-256 是 genesis hash。每条事件包含上一哈希，并对除 `event_hash` 外的完整事件做 canonical JSON SHA-256。独立复核器重新生成参考价、信号与客户订单，校验动作/成交，重算账本、终值、得分与哈希链。

## 7. 位置公平

单局允许 A/B 位置进入公开余数轮换。正式比较必须对同一隐藏环境运行双局换边并取平均；单局结果不得直接作为排名依据。
