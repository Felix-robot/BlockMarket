# BlockMarket 玩家指南

## 一句话目标

写一个 Bot，在 300 轮里通过报价争夺客户订单，让自己的终局净资产高于对手。你赚多少相对优势，对手就得到多少相对劣势。

## 每轮你知道什么

Bot 会收到：

- 当前参考价和全部参考价历史；
- 一个 `UP` 或 `DOWN` 信号，以及信号历史；这个信号有 65% 概率正确描述下一轮方向；
- 自己的现金、库存、累计费用和当前权益；
- 上轮成交、双方累计成交量、剩余轮数与所有报价边界。

Bot 不知道本轮客户是普通还是知情订单，也不知道其方向、数量、保留价和生成密钥；它同样看不到对手本轮尚未结算的动作。

## 每轮你做什么

提交一条动作：

```json
{
  "decision_seq": 17,
  "bid": {"price": "99.55", "quantity": "7"},
  "ask": null
}
```

- `bid`：你愿意买入的最高价；客户卖给出价最高且达到其保留价的 Bot。
- `ask`：你愿意卖出的最低价；客户从要价最低且不超过其保留价的 Bot 购买。
- 任一侧可为 `null`，两侧都为 `null` 就是 `HOLD`。
- 价格必须是 `50.00`–`150.00` 的两位小数字符串；每侧数量是 `1`–`10` 的整数字符串；同时报价时必须 `bid < ask`。

格式、序号或范围有任何错误，整条动作在该轮按 `HOLD`，不会由引擎自动修正。

## 为什么不是“价差越窄越好”

90% 的客户是普通订单，10% 是知情订单。知情订单的买卖方向与下一轮真实价格变化一致，而且通常更激进：它们倾向于在上涨前从你这里买、在下跌前卖给你。

因此策略之间存在真实取舍：

- 窄价差：更容易抢到普通流量，也更容易遭受逆向选择；
- 跟信号单边报价：避开预计危险的一侧，但错误信号会让你错失成交或站错边；
- 宽价差：每笔潜在利润更大，成交机会更少；
- 库存倾斜：能控制终局风险，但可能被对手用更优价抢走流量；
- 对手适应：可以针对对手当前行为，但错误识别会付出代价。

参考策略中已经存在 `SignalFollower > TightSpread > OpponentAdaptive > SignalFollower` 的循环，所以“复制一个固定最优 Bot”不是当前玩法的答案。

## 一个示意轮次

假设当前参考价是 `100.00`，信号为 `UP`：

- A 相信信号，只挂 `bid 99.55 × 7`，不挂卖单；
- B 追求成交，挂 `bid 99.80 × 10 / ask 100.20 × 10`；
- 隐藏客户恰好是知情买单，保留价高于 `100.20`。

B 以 `100.20` 卖出，下一轮若价格上涨，B 承受逆向选择；A 因撤掉卖侧避开它。可是如果本轮是普通卖单，B 的高买价又更可能抢到成交，A 的保守会失去机会。Bot 的工作就是在这种不确定性里根据价格、信号、库存和对手行为动态选择。

## 胜负怎么计算

成交会改变现金、库存并产生 5 bps 费用。最后一个区块结束后，系统用只由隐藏环境决定的终值价格给库存估值：

```text
wealth = cash + inventory * terminal_price - fees
score_A = (wealth_A - wealth_B) / initial_wealth
score_B = -score_A
```

客户只在当轮最优价格层成交；同价时按双方实际可成交容量比例分配，完全相等的余数按公开规则轮换。正式比较会在完全相同的隐藏环境上交换 A/B 位置再取平均。

## 从哪里开始写 Bot

- Python：`starter_kits/python/bot.py`
- TypeScript：`starter_kits/typescript/bot.ts`
- 无需安装 TypeScript 也可直接运行：`starter_kits/typescript/bot.mjs`
- 进程协议与错误语义：[BOT_PROTOCOL.md](BOT_PROTOCOL.md)

先复制 starter kit，只修改 `decide` 函数。开发时用少量区块快速对局，再用多初值换边矩阵检查自己的策略是否只是吃到了一个位置或一条路径的偶然性。

## 边界

BlockMarket 是合成市场编程游戏，不产生真实收益，不连接交易所、钱包、券商或真实资金。当前本地 runner 也不是安全沙箱，不应直接运行来源不明的公开代码。
